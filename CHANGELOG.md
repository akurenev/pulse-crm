# Журнал изменений Pulse CRM

Здесь фиксируются заметные пользовательские, эксплуатационные и совместимые с
API изменения. Production-реквизиты, реальные домены и секреты в журнал не
включаются.

## Unreleased — 31 августа 2026 года

### Добавлено

- Управление воронками: создание и переименование воронки, добавление рабочего
  этапа, изменение названия и цвета этапа.
- Безопасное удаление неиспользуемого рабочего этапа и не последней
  неиспользуемой воронки с проверкой связанных сделок и настроек.
- Optimistic locking для операций настройки воронок и понятные ответы HTTP 409
  при конфликте версии или наличии зависимостей.
- Иллюстрированное Markdown-руководство пользователя и обновлённое руководство
  администратора.
- Теги сделок в API и интерфейсе: отображение в Kanban/списке, поиск и
  редактирование из карточки; теги контактов показываются в списке и карточке.
- Импорт тегов компаний, контактов и сделок из amoCRM с нормализацией и
  идемпотентным backfill ранее перенесённых сделок.
- Запрещённая по умолчанию owner-only политика будущего CRM-экспорта,
  `no-store` для API, минимизированный SSE payload и аудит выдачи временных
  ссылок.
- Персональный лимит продолжения cursor-pagination с HTTP 429 и аудитом
  превышения, затрудняющий быструю последовательную выгрузку CRM-списков.
- Cursor-пагинация по 25 записей для контактов, компаний и задач; закрытые
  задачи скрыты по умолчанию и доступны по отдельной кнопке.
- Административное удаление пользовательских полей сделок с очисткой
  обязательности этапов и сохранением исторических JSON-значений.
- Загрузка выигранных и проигранных этапов сделок только по явному запросу из
  соответствующей колонки Kanban.
- Редактирование и подтверждаемое удаление контактов и задач в десктопном и
  мобильном интерфейсе; операции защищены проверкой актуальной версии записи.
- Назначение и снятие ответственного в карточке сделки с проверкой сотрудника
  текущего workspace и optimistic locking.
- Подтверждаемое versioned soft-delete сделок: активное расписание следующей
  покупки, созданная по нему открытая задача и ожидающие напоминания отменяются,
  а `deal.deleted` остаётся в аудите, outbox и realtime.
- Выбор любой активной воронки и согласованного этапа в настройках каналов,
  webhook-ов, HTML-форм и правил оповещений; правила поддерживают фильтр по всей
  воронке без обязательного этапа.
- Мобильные круглые кнопки **+** для добавления корпоративного канала и правила
  оповещения над нижней навигацией.
- Персональные Web Push-уведомления для установленной PWA: подписка отдельного
  устройства, тестовая отправка, отключение и безопасная очистка при выходе.
- Безопасные внутренние ссылки из Web Push прямо в связанную сделку или задачу,
  включая восстановление перехода после входа и загрузку объекта вне текущей
  страницы списка.
- Ограниченная роль **Сотрудник**: только назначенные ему сделки, контакты и
  задачи; создание и изменение своих записей без переназначения,
  самостоятельного управления компаниями, настроек и удаления CRM-записей.
  Контакты получили явного ответственного.
- Отдельные приватные вложения внутренних заметок сделки: до пяти файлов,
  атомарное сохранение, защищённое скачивание и явное отделение от переписки с
  клиентом.
- Редактирование действующих пользователей, каналов и правил оповещений с
  optimistic locking, безопасным сохранением секретов и повторной проверкой
  клиентского согласия при смене получателя или канала.
- Подтверждаемое удаление компаний с сохранением связанных контактов и сделок,
  у которых связь с удалённой компанией снимается.
- Редактирование компаний и двусторонние переходы между карточками контактов,
  компаний и сделок, включая загрузку связанной записи вне текущей страницы.
- Серверный поиск сделок по всем этапам выбранной воронки: по данным сделки,
  связанного контакта и компании, с продолжением результатов по cursor.

### Исправлено

- Этапы amoCRM идентифицируются парой `pipeline_id:status_id`. Одинаковые
  системные status ID в разных воронках больше не считаются дублями, а сделки
  связываются с этапом своей воронки.
- Сохранена совместимость с ранее созданными сопоставлениями этапов по одному
  status ID; повторный импорт остаётся идемпотентным.
- Alembic не предлагает удалить PostgreSQL GIN-индексы полнотекстового поиска,
  которыми управляет явная миграция.
- Backend CI разделяет окружение проверки PostgreSQL-миграций и изолированных
  тестов приложения.
- Административные операции и исполнение доменных фоновых заданий ограничены
  текущим workspace.
- Kanban сохраняет одну горизонтально прокручиваемую строку на телефоне,
  планшете и десктопе; мобильный список сделок больше не накладывает поля друг
  на друга.
- Переключение воронок не ждёт повторной загрузки справочников и связанных
  задач; cursor-запросы сделок, клиентов и задач получили составные индексы.
- Контакты без реального ответственного больше не получают демонстрационного
  сотрудника; медленные запросы списков можно повторить из интерфейса.
- Локально удалённое поле amoCRM не активируется повторным импортом.
- Новое SSE-подключение больше не воспроизводит всю историю workspace;
  резервный 15-секундный опрос работает только при разрыве realtime-соединения,
  а пачки событий объединяются в одно обновление интерфейса.
- Concurrent-миграция индексов CRM-списков безопасно продолжается после
  прерванного запуска контейнера: готовые индексы пропускаются, незавершённые
  пересоздаются, конфликтующая структура отклоняется.
- Row-level scope сотрудника распространён на карточки, dashboard, activity,
  сообщения, вложения, согласия, realtime и уведомления; переназначение сразу
  отзывает доступ прежнего ответственного, а отложенная доставка повторно
  проверяет текущего ответственного и доступ к целевому объекту.
- Повторный импорт amoCRM синхронизирует владельца и основной контакт активного
  расписания следующей покупки и связанной открытой задачи; несопоставленная
  сделка больше не оставляет производные данные прежнему сотруднику.
- Карточка сделки разделена на пять вкладок: пользовательские поля вынесены в
  **Поля**, заметки — в **Детали**; ошибки загрузки заметок и истории больше не
  маскируются под пустой список.
- Список сделок использует адаптивные карточки и на широком экране, задачи
  открываются нажатием по строке и ведут в связанную сделку, а кнопки удаления
  контактов и компаний приведены к единому виду.
- Поиск компаний по Email и телефону больше не скрывает найденную сервером
  запись из-за повторной локальной фильтрации устаревшего ответа.

### Документация

- Состав импорта amoCRM явно включает воронки, этапы, метаданные и сопоставления
  пользователей, поля, компании, контакты, сделки, открытые задачи и обычные
  заметки; учётные записи Pulse CRM при этом не создаются.
- Инструкции развёртывания обезличены: используются только плейсхолдеры без
  параметров конкретного production-контура.
- Канонической инструкцией остаётся Markdown; дублирующие DOCX-копия и её
  генератор удалены, а проверка руководств закреплена в `CONTRIBUTING.md`,
  `AGENTS.md` и шаблоне PR.
