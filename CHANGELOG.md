# Журнал изменений Pulse CRM

Здесь фиксируются заметные пользовательские, эксплуатационные и совместимые с
API изменения. Production-реквизиты, реальные домены и секреты в журнал не
включаются.

## Unreleased — 29 августа 2026 года

### Добавлено

- Управление воронками: создание и переименование воронки, добавление рабочего
  этапа, изменение названия и цвета этапа.
- Безопасное удаление неиспользуемого рабочего этапа и не последней
  неиспользуемой воронки с проверкой связанных сделок и настроек.
- Optimistic locking для операций настройки воронок и понятные ответы HTTP 409
  при конфликте версии или наличии зависимостей.
- Иллюстрированное Markdown-руководство пользователя и обновлённое руководство
  администратора.
- Теги сделок в API и интерфейсе: отображение в Kanban/списке, поиск и
  редактирование из карточки; теги контактов показываются в списке и карточке.
- Импорт тегов компаний, контактов и сделок из amoCRM с нормализацией и
  идемпотентным backfill ранее перенесённых сделок.
- Запрещённая по умолчанию owner-only политика будущего CRM-экспорта,
  `no-store` для API, минимизированный SSE payload и аудит выдачи временных
  ссылок.
- Персональный лимит продолжения cursor-pagination с HTTP 429 и аудитом
  превышения, затрудняющий быструю последовательную выгрузку CRM-списков.
- Cursor-пагинация по 25 записей для контактов, компаний и задач; закрытые
  задачи скрыты по умолчанию и доступны по отдельной кнопке.
- Административное удаление пользовательских полей сделок с очисткой
  обязательности этапов и сохранением исторических JSON-значений.
- Загрузка выигранных и проигранных этапов сделок только по явному запросу из
  соответствующей колонки Kanban.

### Исправлено

- Этапы amoCRM идентифицируются парой `pipeline_id:status_id`. Одинаковые
  системные status ID в разных воронках больше не считаются дублями, а сделки
  связываются с этапом своей воронки.
- Сохранена совместимость с ранее созданными сопоставлениями этапов по одному
  status ID; повторный импорт остаётся идемпотентным.
- Alembic не предлагает удалить PostgreSQL GIN-индексы полнотекстового поиска,
  которыми управляет явная миграция.
- Backend CI разделяет окружение проверки PostgreSQL-миграций и изолированных
  тестов приложения.
- Административные операции и исполнение доменных фоновых заданий ограничены
  текущим workspace.
- Kanban сохраняет одну горизонтально прокручиваемую строку на телефоне,
  планшете и десктопе; мобильный список сделок больше не накладывает поля друг
  на друга.
- Переключение воронок не ждёт повторной загрузки справочников и связанных
  задач; cursor-запросы сделок, клиентов и задач получили составные индексы.
- Контакты без реального ответственного больше не получают демонстрационного
  сотрудника; медленные запросы списков можно повторить из интерфейса.
- Локально удалённое поле amoCRM не активируется повторным импортом.

### Документация

- Состав импорта amoCRM явно включает воронки, этапы, пользователей, поля,
  компании, контакты, сделки, открытые задачи и обычные заметки.
- Инструкции развёртывания обезличены: используются только плейсхолдеры без
  параметров конкретного production-контура.
- Канонической инструкцией остаётся Markdown; дублирующие DOCX-копия и её
  генератор удалены, а проверка руководств закреплена в `CONTRIBUTING.md`,
  `AGENTS.md` и шаблоне PR.
