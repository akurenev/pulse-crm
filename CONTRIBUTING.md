# Участие в разработке Pulse CRM

Спасибо за желание помочь проекту. Мы принимаем исправления ошибок,
документацию, тесты и небольшие, хорошо обоснованные улучшения MVP.

## Перед началом

- Для ошибки или заметного изменения сначала найдите существующий issue.
- Для новой крупной функции откройте discussion/issue и согласуйте границы до
  реализации. Функции вне текущего MVP могут быть отложены.
- Уязвимости нельзя публиковать в обычных issues: следуйте
  [SECURITY.md](SECURITY.md).
- Общайтесь уважительно и описывайте технические аргументы предметно.

## Локальное окружение

Самый короткий путь:

```bash
cp .env.example .env
docker compose up --build
```

Подробный контейнерный и host-native запуск описан в [README.md](README.md).
Никогда не коммитьте `.env`, токены, выгрузки клиентов или реальные сообщения.

## Рабочий процесс

1. Создайте небольшую ветку от актуального `main`.
2. Ограничьте pull request одной логической задачей.
3. Для изменения модели данных добавьте Alembic-миграцию. Миграции должны быть
   совместимы с откатом приложения по подходу expand/contract.
4. Для изменения поведения добавьте или обновите тесты.
5. После каждого функционального изменения обязательно перечитайте и при
   необходимости обновите Markdown-инструкции: пользовательские сценарии — в
   `docs/user-guide.md`, настройки администратора — в `docs/admin-guide.md`.
   Даже если правка не требуется, это нужно отметить в описании PR.
6. Обновите OpenAPI-типы и `.env.example`, если меняется публичный контракт или
   конфигурация. Не поддерживайте параллельные DOCX-копии инструкций: каноническая
   документация проекта хранится в Markdown и проверяется вместе с кодом.
7. Перед отправкой выполните проверки ниже.

Backend:

```bash
python -m pip install -e "backend[dev]"
ruff check backend/app backend/tests
mypy backend/app
python -m pytest backend/tests

# TEST_DATABASE_URL указывает только на одноразовую тестовую PostgreSQL.
test -n "$TEST_DATABASE_URL"
PULSE_DATABASE_URL="$TEST_DATABASE_URL" alembic -c backend/alembic.ini upgrade head
PULSE_DATABASE_URL="$TEST_DATABASE_URL" alembic -c backend/alembic.ini check
```

Frontend:

```bash
cd frontend
npm ci
npm run lint
npm run typecheck
npm run test
npm run build
npm run test:e2e
```

Production image:

```bash
docker build -t pulse-crm:local .
```

## Требования к изменениям

- Каждый запрос к бизнес-данным должен быть ограничен `workspace_id`.
- Интеграции и фоновые задания должны быть идемпотентны.
- Событие outbox и доменное изменение сохраняются одной транзакцией.
- Секреты, содержимое сообщений и файлов не попадают в логи.
- API остаётся под `/api/v1`; несовместимое изменение требует отдельного
  обсуждения.
- Интерфейс проверяется на ширинах 360, 768 и 1440 px, с клавиатуры и без мыши.
- В production остаются один webapp, одна PostgreSQL и один приватный S3.
- PostgreSQL-specific индекс, созданный raw DDL, нужно добавить в список
  управляемых миграцией объектов в `backend/alembic/env.py`; обычные индексы
  должны оставаться видимыми для `alembic check`.

Публичный репозиторий не должен содержать параметры реального контура. В issue,
PR, документации, fixtures и скриншотах используйте только вымышленные домены,
IP и идентификаторы. Не публикуйте connection strings, bucket/network names,
OAuth-реквизиты, bot tokens, дампы, сообщения клиентов и production-логи.

Не запускайте formatter по несвязанным файлам и не включайте в PR generated
артефакты (`dist`, coverage, Playwright reports).

## Pull request

В описании укажите проблему, выбранное решение, способ проверки, изменение
миграций/конфигурации и скриншоты для UI. Отдельно укажите, какие разделы
`docs/user-guide.md` и `docs/admin-guide.md` проверены и что в них изменено.
CI должен быть зелёным. Maintainer может попросить разделить большой PR или
добавить тесты.
