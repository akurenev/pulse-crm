# ADR-0001: единый webapp с PostgreSQL-backed фоновой обработкой

- Статус: принято
- Дата: 2026-08-27

## Контекст

MVP разворачивается для одной компании и должен оставаться простым в
эксплуатации. Production-бюджет и операционная модель допускают ровно один
Timeweb App Platform webapp, одну PostgreSQL DBaaS и один приватный S3-бакет.
При этом нужны отложенные уведомления, импорт, polling почты, повторные
отправки и восстановление после перезапуска.

## Решение

React SPA собирается в production-образ и обслуживается FastAPI с того же
origin. FastAPI работает одним процессом Uvicorn. В `lifespan` запускается
контролируемый supervisor; durable state фоновой обработки хранится в
PostgreSQL.

```text
Browser / bots / email / forms
              │
              ▼
   FastAPI + React + supervisor
        │                │
        ▼                ▼
   PostgreSQL        private S3
```

Инварианты решения:

- API и фоновые циклы принадлежат одному процессу и одной реплике;
- очередь захватывает строки через `FOR UPDATE SKIP LOCKED` и выдаёт lease;
- просроченный lease безопасно возвращается в очередь;
- `dedupe_key` и доменные проверки обеспечивают идемпотентность;
- бизнес-изменение, `ActivityEvent`, `OutboxEvent` и `RealtimeEvent`
  фиксируются одной транзакцией;
- supervisor не выполняет блокирующий ввод-вывод в event loop и ограничивает
  конкурентность четырьмя заданиями;
- `/health/ready` возвращает 503 при недоступной БД или stale heartbeat;
- вложения остаются приватными и доступны только по короткоживущей signed URL.

## Последствия

Плюсы: один deployable artifact, нет Redis/Celery, простой backup и понятная
трассировка транзакций. Минусы: фоновые задачи конкурируют за CPU/RAM с API,
одна реплика является пределом MVP, а длительные операции требуется дробить
на задания короче 30 секунд.

Горизонтальное масштабирование или отдельный worker требуют нового ADR. До
этого момента App Platform должен запускать ровно одну реплику и один Uvicorn
worker.
